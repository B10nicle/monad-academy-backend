# Monad Academy Project Context

## Product

Monad Academy is a learning and coding practice web application inspired by LeetCode and Codewars, but intentionally simpler.

The product will have two repositories:

- `monad-academy-backend`: Java backend API.
- `monad-academy-frontend`: Angular frontend, to be created later.

## Backend

Repository: `git@github.com:B10nicle/monad-academy-backend.git`

Current backend stack:

- Java 25
- Spring Boot 4.0.6
- Maven Wrapper
- Spring Web MVC
- Spring Security
- Spring Validation
- Spring Data JPA
- PostgreSQL
- Liquibase
- Spring Boot Actuator
- Docker Compose support
- H2 for tests only

Main package:

```text
com.monadacademy.backend
```

Important files:

- `pom.xml`: Maven build and dependencies.
- `compose.yaml`: local PostgreSQL service.
- `src/main/resources/application.yml`: application configuration.
- `src/main/resources/db/changelog/db.changelog-master.yaml`: Liquibase master changelog.
- `src/main/java/com/monadacademy/backend/config/SecurityConfig.java`: initial security configuration.
- `src/test/resources/application-test.yml`: test profile using H2.

## Frontend

Frontend repository has not been created yet.

Planned stack:

- Angular 21

Reasoning: Angular 21 is the current suitable stable major for starting the frontend. Angular 22 was expected after this backend setup date, so it should be rechecked before creating the frontend repository.

## Git Workflow

Permanent branches:

- `main`
- `develop`

Feature work should start from `develop`:

```bash
git switch develop
git pull --ff-only origin develop
git switch -c feature/<name>
```

After a feature is merged into `develop`, delete the feature branch locally and remotely:

```bash
git branch -d feature/<name>
git push origin --delete feature/<name>
```

Current rule from the project owner: always remove feature branches after merge.

Pull requests should be created by the GitHub App actor when possible, not by the repository owner account. Use:

```bash
GH_TOKEN="$(scripts/github-app-token.sh)" gh pr create ...
```

Always request `B10nicle` as reviewer on new pull requests:

```bash
GH_TOKEN="$(scripts/github-app-token.sh)" gh pr edit <pr-number> --add-reviewer B10nicle
```

The GitHub App setup uses:

- App ID: `3838241`
- Installation ID: `135150810`
- Private key path: `.secrets/monad-academy-agent.private-key.pem`

The `.secrets/` directory must stay untracked.

## Local Commands

Run tests:

```bash
./mvnw test
```

Start local PostgreSQL:

```bash
docker compose up -d
```

Run the backend:

```bash
./mvnw spring-boot:run
```

## Collaboration Notes

When adding backend functionality:

- Prefer focused feature branches from `develop`.
- Open pull requests with the GitHub App token when possible and add `B10nicle` as reviewer.
- Keep migrations in Liquibase.
- Keep tests runnable without local PostgreSQL by using the `test` profile and H2 where practical.
- Use Spring Boot 4 conventions generated by Initializr, including `spring-boot-starter-webmvc`.
- Keep `develop` clean and push changes only after tests pass when feasible.
